# SC2336 摄像头预览套路（openvela × NuttX video + MIPI-CSI）

## 使用时机

- 摄像头无画面、取流接口报格式 / 尺寸错误
- 预览花屏、绿紫「迷幻色」、高饱和五彩噪声
- 预览撕裂、帧率与预期不符

## Step 0：本板链路事实

- 传感器 SC2336（2MP，RAW Bayer），MIPI-CSI 2 lane，XVCLK 由子板 24MHz 晶振提供（`pins.md`）。
- 传感器控制面 SCCB **复用 I2C0**（SCL=8/SDA=7，地址 0x3C）；板级驱动 `esp32p4_sc2336.c` 提供流开关（本仓 `app/signbridge/signbridge_camera.c` 引用）。
- 采集为 NuttX video 框架内自研路径：DW-GDMA 将摄像头数据**直写 PSRAM 双缓冲**并附帧回调，控制面经 SCCB 独立配置（nuttx PR #347）。
- 已实现并编译通过的预览链路：lvgldemo camera 模块（nuttx-apps PR #123），SC2336 RAW 1280×720@30fps，DMA→PSRAM 双缓冲。**signbridge 应用侧帧源接入与整机联调属待复验项**（README §7.1）——本技能现象表为板级 / 芯片级原理与设计原则，整机实测数据以复验为准。

## Step 1：症状 → 根因 → 处置原则

| 症状 | 根因 | 处置原则 |
|------|------|----------|
| 取流接口拒绝分辨率请求 | CSI 只接受与 sensor 当前模式**完全一致**的分辨率，不支持缩放（本板实测 1008×567 与 1920×1080 均被拒） | 用 sensor 原生 720p 取流 + **软件裁切**（lvgldemo camera 模块即按 720p 原生模式实现） |
| 绿紫「迷幻色」（结构可辨） | 色彩链路无 AWB/AE 校正闭环，硬件裸跑 RAW 直出 | 在驱动 / 后处理层补校色——NuttX 侧无现成 ISP 管线配置，属自研设计决策点，须先明确再动手 |
| 高饱和五彩噪声 | RAW8 输入下解马赛克链路不工作 | 使用 sensor 原生 **RAW10** 位深，勿用 RAW8 默认模式 |
| 颜色通道错乱（偏色但结构正常） | RAW→RGB 转换的字节序或 R/B 组件序差异 | 逐像素转换排查：**先试通道换（R↔B），再试字节换**，二者视觉表现不同 |
| 预览大面积撕裂 | 显示刷新与帧拷贝竞争同一缓冲 | 同步刷新或原子帧交接（见 Step 3） |
| PPA 搬运出现整屏细密竖向列噪声（UI 层干净） | PPA 与 LVGL 叠加存在上游已知缺陷 | 叠加场景禁用，回退 CPU 拷贝（见 Step 2） |

## Step 2：帧搬运方式选型（LVGL 叠加场景）

| 方式 | 结论 |
|------|------|
| PPA 硬件搬运（SRM 裁切 / 缩放） | ❌ 叠加场景禁用——上游已知缺陷（PPA 加速引发撕裂与错误重绘）；仅用于无 UI 叠加路径并留软件回退开关 |
| CPU 逐行拷贝 | ✅ 叠加场景可靠回退；牺牲帧率换正确性 |
| 全屏无 UI 直写 framebuffer | ✅ 无叠加场景的正解，零拷贝 |

## Step 3：防撕裂帧交接设计（原则）

- **原子单槽发布**：生产者（DMA 帧回调）只发布最新完整帧，消费者只读已发布帧。
- **延迟一帧归还缓冲**：防止 DMA 覆写正在被读取的内存。
- **迟到帧直接回收**：处理不完的帧丢弃不排队——**丢帧优于撕裂**。

## Step 4：帧缓冲诊断（先拿证据再动手）

1. 帧字节数核对：RGB565 1280×720 应为 **1,843,200** 字节；若恰为 921,600，说明数据实为 RAW8 未转换。
2. 帧中心行 hex dump：平滑渐变的高字节 + 噪声状低字节 = RAW 排布（未转 RGB）；大面积 `FF` = 白墙场景的正常 RGB565。
3. 传感器在位以 I2C 探测为准（控制面走通后流开关 `esp32p4_sc2336_stream()` 才有意义）。

## 注意事项

- **严禁凭猜连续试错**：先做 Step 4 诊断拿证据，再对照本表定位。
- 摄像头 SCCB 与触摸 / 音频共用 I2C0：SCCB 操作异常可能同时表现为触摸失灵，交叉排查见 `touch-gt911-debug` 技能。
- 整机取流复验完成前，本技能不得作为「摄像头链路已验收」的依据引用。
