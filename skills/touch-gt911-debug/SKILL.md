# GT911 触摸排障（openvela × gt9xx 轮询驱动）

## 使用时机

- 触摸完全无响应，重启也无效
- 驱动不挂载 / 探测不到器件
- 局部区域点不动、整屏被拖动、按钮点不到、点了 A 响应 B、坐标偏移

## Step 0：本板硬件前提（先读，`pins.md`）

- 触摸 **INT_TP / RESET_TP 均不接（NC）**：仅引出至适配板 J6 排针（INT=J6-pin5，RESET=J6-pin8，引脚号为中等置信度，飞线前万用表复核），主控侧无中断、无复位线 → **轮询模式**是本板唯一软件形态。
- 上电 INT 悬空 → I2C 地址锁存 **0x5D**；0x14 需外部将 INT 拉高。驱动已支持 **0x5D/0x14 双地址自动探测**（nuttx PR #364）。
- 与音频 codec（ES8311，0x18）、摄像头 SCCB（SC2336，0x3C）**共用 I2C0**（SCL=8/SDA=7，400kHz）。

## Step 1：症状 → 根因 → 处置

| 症状 | 根因 | 处置 |
|------|------|------|
| 触摸**完全失效**，软复位无效 | I2C 总线被此前中止的事务卡死，热复位清不掉 | **完全断电 10 秒**再上电 |
| 多次重试后触摸永久失效 | GT911 的 I2C ack **重试超过一次即进入永久 NACK**（芯片级行为，PR #364 实证） | 驱动红线：ack 只尝试一次；唯一恢复手段为断电重启；连续失败触发 `I2C_RESET` 总线恢复 |
| 探测不到器件 / 挂错地址 | Kconfig 接线描述与实物不符（移植期实证：描述 INT=GPIO9/RESET=GPIO45，实物 NC，#347） | 以原理图 + 实物核对修正配置；确认地址探测覆盖 0x5D/0x14 两形态 |
| I2C 偶发失败引发雪崩 | 分段事务（地址、数据分多条消息）在共享总线上留下中间态 | 寄存器地址与数据**合并为单条 I2C 消息**（PR #364 的 gt9xx 设计） |
| 失败风暴刷屏日志 | 无节流的错误日志 | 重试**有界**（上限 4 次、间隔 5ms、连续失败日志节流），每 25 次连续失败才触发一次总线恢复（PR #364） |
| 局部区域点击无响应、其他区域正常 | 底层控件残留 `LV_OBJ_FLAG_CLICKABLE` 吞掉事件 | 非交互控件清除 CLICKABLE |
| 整屏可被拖动 / 点击变滚屏 | 屏幕容器可滚动（画布内容溢出屏幕） | 容器禁滚 + 关滚动条 |
| 某按钮怎么点都没反应 | 被软键盘 / 浮层完全遮挡 | 先量控件 y 区间再下结论，布局错开 |
| 点 A 恒响应 B / 索引恒为 0 | 索引写入与读取通道不一致（写进控件 user_data、却从事件 user_data 读，或反之） | 索引统一走同一通道 |
| 坐标方向镜像 / 偏移 | 本板 gt9xx 驱动**不做 mirror_x/mirror_y**（官方参考实现做了镜像），方向映射属待核对项（`pins.md`） | 真机核对触摸坐标与显示坐标；可用驱动新增的事件计数 ioctl 辅助定位 |

## Step 2：验证手段

1. 驱动事件统计接口：gt9xx 提供 down / move / up / drop / **ack_fail** 计数 ioctl（PR #364），先看计数器再猜代码。
2. 临时坐标打印核对映射（四角 + 中心 + 边缘极限 + 滑动不误触）。
3. 断电恢复后复测——若断电即自愈，问题在总线态不在代码。

## 注意事项

- 触摸失效**先断电 10 秒**再排查代码——总线卡死是物理态，热复位无效，盲目改代码白费。
- 排查共享总线时注意同总线外设（音频 / 摄像头 SCCB）的相互影响；SCCB 操作异常也可能拖死触摸。
- 触摸初始化失败**不阻塞整机**：降级启动，无触摸时显示与播报仍可用。
